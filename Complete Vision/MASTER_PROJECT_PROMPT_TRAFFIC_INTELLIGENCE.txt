## 2. OVERALL RESEARCH OBJECTIVE

Develop a modular intelligent traffic analysis system capable of:

1. Detecting different vehicle categories.
2. Detecting and segmenting road lane markings.
3. Identifying drivable road areas.
4. Tracking individual vehicles across video frames.
5. Analysing vehicle movement and trajectories.
6. Recognizing selected traffic behaviours and potential violations.
7. Presenting the results through a usable traffic intelligence application.

The research should investigate whether custom neural network architectures and temporal contextual learning can improve traffic scene understanding and behaviour recognition under challenging road conditions.

Potential research question:

"Can combining spatial road understanding with temporal vehicle movement analysis improve the reliability of traffic behaviour recognition compared with independent frame-based predictions?"

Investigate performance under:
- Partial vehicle occlusion.
- Different lighting conditions.
- Shadows and reflections.
- Curved roads.
- Faded or unclear lane markings.
- Dense traffic.
- Different camera perspectives.
- Incomplete observations.

Do not claim novelty without conducting a literature review and identifying a defensible research gap.

## 6. MODEL DEVELOPMENT

### MODULE A — LANE DETECTION

This is our first priority because the TuSimple dataset is already available.

Research objective:

Build and compare custom neural network approaches for lane detection.

Model A1: Custom CNN-based lane segmentation network.

Model A2: Custom U-Net.

Model A3: CNN-based direct lane-coordinate prediction.

Optional Model A4: Lightweight Vision Transformer or hybrid CNN-Transformer segmentation model.

Implement these architectures ourselves rather than simply loading an existing pretrained lane detector.

Investigate:
- Encoder architecture.
- Feature extraction.
- Multi-scale feature fusion.
- Decoder design.
- Skip connections.
- Output representation.
- Loss functions.
- Optimization.

For segmentation, investigate:
- Binary lane masks.
- Multi-class lane masks if the available labels support them.
- Dice loss.
- Binary cross-entropy.
- Combined BCE and Dice loss.

For coordinate prediction, investigate an appropriate coordinate or structured lane prediction loss.

Evaluation:
- Intersection over Union.
- Dice coefficient.
- Precision.
- Recall.
- Pixel accuracy.
- Official TuSimple benchmark metric where compatible.
- Inference latency.
- FPS.

Keep coordinate benchmark metrics and segmentation metrics separate.

Do not compare two models using incompatible output definitions without explaining the difference.

### MODULE B — VEHICLE DETECTION

Use BDD100K detection annotations where available.

Develop a lightweight custom detector:

- Custom CNN backbone.
- Multi-scale feature extraction.
- Feature pyramid where feasible.
- Detection head.
- Bounding-box regression.
- Object classification.

Use an appropriate detection loss.

Train the custom architecture from random initialization for the primary experiment.

A pretrained detector may be used as an external baseline, but it must not replace the custom model.

Potential classes:
- Car.
- Motorcycle.
- Bus.
- Truck.
- Three-wheeler only if suitable annotations are available.

Do not invent missing classes or relabel unrelated objects.

Evaluation:
- mAP@0.5.
- mAP@0.5:0.95.
- Precision.
- Recall.
- Per-class AP.
- FPS.
- Model size.

### MODULE C — ROAD SEGMENTATION

Use verified BDD100K drivable-area annotations where available.

Investigate:
- Custom U-Net.
- DeepLabV3+ comparison.
- Lightweight encoder-decoder architecture.

Evaluate:
- Mean IoU.
- Dice.
- Pixel accuracy.
- Per-class performance where applicable.

### MODULE D — VEHICLE TRACKING

Use a tracking method such as ByteTrack after object detection.

Track each detected vehicle across frames.

Extract:
- Track ID.
- Bounding-box centre.
- Position.
- Estimated direction.
- Displacement.
- Approximate speed where camera calibration supports it.
- Lane association.
- Trajectory history.

Important:
Pixel displacement is not automatically real-world speed.

Do not report km/h without calibration or a defensible conversion method.

### MODULE E — TEMPORAL TRAFFIC BEHAVIOUR

This is the higher-level research component.

Potential events:

1. Wrong-way movement.
2. Red-light violation.
3. Illegal lane change.
4. Lane departure.
5. Unusual or anomalous vehicle movement.

These events require proper temporal labels or rule-based ground truth.

Do not assume a lane change is illegal.

Do not infer red-light violations without traffic-light state and stop-line information.

Do not infer wrong-way driving without road direction and lane geometry.

Develop:

Model E1: CNN + LSTM.

Model E2: Temporal Transformer.

Possible input features:

- Vehicle position history.
- Direction.
- Displacement.
- Lane association.
- Lane boundary crossing.
- Traffic signal state.
- Stop-line crossing.
- Relative vehicle movement.
- Observation confidence.

Use fixed-length temporal sequences.

Explore 16-frame and 32-frame sequences as initial configurations, subject to hardware constraints.

Evaluation:
- Macro F1.
- Precision.
- Recall.
- Per-class F1.
- Confusion matrix.
- Event-level precision and recall.
- False-positive rate.
- Inference latency.

Create or obtain a verified event dataset before training a supervised violation classifier.

If only a small annotated dataset is available, clearly describe the limitations and use rule-based event detection as a separately evaluated baseline.
